## 1. 实验应当产出什么

这次实验已经足够支持开始设计一个更好的 Markit AST 更新器。下一步是把确认的优势组合成最小研究实现，验证尚未证明的设计选择。

目标是：**编辑影响多大，就处理多大的语法和语义；未受影响的部分，既不重新解析，也不逐条维护。**

“更好”同时考虑首次解析、编辑更新、常驻内存、最坏退化与实现复杂度。局部更新不能靠隐藏语义计算、把维护移到查询、复制 source 或无限保存旧版本获得表面优势。

| 实验教训 | 对 Markit 的要求 |
|---|---|
| H1 用小解析区域获得大幅收益 | 准确定位 damage，并保留边界 continuation 检查 |
| H4 在安全位置重启，状态一致后停止 | 支持 restart/convergence |
| H4 复用 AST 后仍大量维护后缀 | 位置、索引、checkpoint 必须支持局部更新 |
| H2 区分结构保留与语义重做 | 分别判断 syntax 与 semantic payload 的有效性 |
| H3 的复用发现可能比解析更贵 | 旧节点定位必须便宜，不能反复搜索整树 |
| H0 在广泛变化时有优势 | 全量解析是正常算法选择，同时提供 escape |

因此需要共同设计解析算法和 AST 表示：前者回答从哪里开始、在哪里停止；后者回答如何保留结果而不承担全文维护。

## 2. 用一次普通编辑理解目标

文档有一万个段落，在中间一个段落增加几个字：

1. 根据位置索引找到覆盖段落。
2. 从之前的安全边界恢复解析。
3. 重解析段落，必要时继续检查后面的边界。
4. 确认后续解析状态与旧状态一致。
5. 用新结果替换损伤区，保留其他节点。
6. 只更新少量长度汇总信息。

不能为了第 1 步先遍历一万个段落；不能因为后面几千个段落位置偏移就逐条改 offset。块内相对位置与上层长度聚合可以让绝对位置按需计算。

H4 已保留大量解析结果，但尚未让全部状态维护局部化。这是第一项应落实的改进。

## 3. 第一版最小核心

- 权威 Markdown source；
- 可按位置查找、可局部拼接的块序列；
- 块内语法信息与 AST 语义结果；
- 安全边界的 parser continuation。

块序列支持定位、分出前缀、替换损伤区、接回后缀。证据要求这些操作足够局部，尚未要求某种具体 persistent tree。单版本研究原型可以先采用可变结构。

也不必立即维护两棵完整 CST/AST。保存恢复解析、源位置查询、正确 AST 输出和局部 inline 重解析所必需的信息即可。增加的每份长期状态必须说明实际省掉哪项工作。

## 4. 语义变化分阶段解决

```markdown
第一段使用 [项目][project]。

……很多内容……

[project]: /old-url
```

修改 destination 时，第一段块结构仍有效，链接结果需要更新。目标是保留语法，只重新计算依赖该 label 的语义。

为避免扫描全文，候选附加状态是：label→有序定义候选，以及 label→consumer blocks。必须包括当前 unresolved 的引用尝试；仅登记已解析成功的链接会漏掉新增定义的影响。

工程顺序：第一版先完成局部语法更新，定义环境变化仍可全量重建；第二版再加入依赖修复，单独衡量其收益、构建和内存成本。两者不能同时替换后只报告一个总加速比。

## 5. 四个实施步骤

| 步骤 | 内容 | 完成标准 |
|---|---|---|
| 统一目标状态 | 现有语义核心的 full builder 构建新表示 | 与 oracle 一致；记录构建、内存及释放成本 |
| 局部语法更新 | 定位、safe restart、forward parse、convergence、splice | 固定小编辑不遍历未变全文，不逐条维护后缀 |
| 选择性语义修复 | winner 维护、label→consumer blocks | 低 fanout 只处理相应消费者，无全局引用探测 |
| 成本选择 | 已知昂贵情况直接全量；未知传播设预算 | 广泛变化及时停止增量，避免大量重复工作 |

第一优先级是局部语法更新；依赖索引须单独赚取成本；selector 从简单估计和预算起步。

## 6. “更好”的验收含义

- 编辑后的规范化结果与 clean full parse 一致。
- 固定局部编辑随 N 增大，不访问与全文记录数成正比的未变状态。
- 引用变化只修复有效 winner 变化所影响的消费者。
- 广泛损伤时能合理转向全量。
- 构建、常驻内存和索引维护成本不吞掉目标区间收益。

六个小实验 cell 是新实现的判别工具，不是要求重跑 Campaign-2。普通正确性回归仍覆盖现有语义边界。

## 7. 范围与后续模型的任务

本次证据主要支持更好的 AST **更新器**；尚未证明首次 Markdown full parse 更快。首次解析需要高效 full path，长期编辑通过局部更新获益，两者构成同一解析引擎。

后续模型先读完整机制报告，再按设计候选细化数据结构、continuation 和语义依赖算法。先证明小编辑只解析、只维护小部分状态，再决定索引与成本选择的具体实现。不要把 BENCH-GRAMMAR-v1 扩充成产品方言、引入编辑器/UI 框架或恢复归档 core 来代替这项工作。
