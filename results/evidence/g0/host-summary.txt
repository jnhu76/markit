## How the runs were produced

```text
build    rsync PR tree -> C:\markit-g0\src
         cargo build --release -p markit --features g0-probe   (native host)
deploy   copy src\target\release\markit.exe -> C:\markit-g0\markit.exe
matrix   C:\markit-g0\markit.exe --g0-probe --smoke            (canonical)
ime      C:\markit-g0\run-pinyin.ps1  (activates MS Pinyin HKL 0x08040804
         for the probe thread, injects raw keys: n-i-h-a-o + SPACE commit,
         z-h-o-n-g-w-e-n + ESC cancel, F1 dump, restores layout)
scale    display scale set to 125% via Settings (manual), verified by the
         probe's own `G0 scale_factor=1.25` log line; restored to 100%
         afterwards (verified `G0 scale_factor=1` before teardown of G0)
idle     external Get-Process sampling loop while the interactive probe sat
         focused and untouched
```

## Honesty limits (unchanged from the G0 report)

- F2/Q keyboard actions were not separately exercised (same dispatch path
  as F1/F3); mouse coverage is click-only (no drag/wheel).
- IME evidence is pipeline-level: composition start/update, GCS_RESULTSTR
  commit replacing the marked range, ESC cancel clearing it, and candidate
  `bounds_for_range` docking calls. Product-level IME UX (candidate window
  visuals, arrow-key candidate navigation) belongs to P1-A.
- The 2026-08-22 run (superseded probe binary) observed ~12.5/s armed
  `on_next_frame` delivery; the review-fixed binary observed ~60/s at both
  100 % and 125 % (≈ every 60 Hz vsync). Draws stayed ~0 in all runs.
  Callback delivery rate is recorded as run/binary-dependent, not a
  platform contract; the stable claim is "no draw/present work while idle".
